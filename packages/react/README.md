# @coffeejson/react

React components for rendering CoffeeJSON documents. SSR-safe by construction:
pure function components, no effects, no DOM access — `renderToStaticMarkup`
works in any edge/worker runtime.

The components render a document's **beans and recipes**. `normalize` also
projects `tastings`, which no component here renders: a tasting card is the
consumer's, and the projection is there to build it on.

## Install

```sh
npm install @coffeejson/react @coffeejson/core
```

`react` is a peer dependency. This package's version is its own: it says
nothing about the `coffeejson` version a document declares
([Versioning](https://coffeejson.org/docs/spec/07-versioning.md)).

```tsx
import { CoffeeJSONView } from "@coffeejson/react";
import { decodePayload } from "@coffeejson/core";
import "@coffeejson/react/styles.css"; // optional default skin

const result = decodePayload(d);
<CoffeeJSONView doc={result.ok ? result.document : null}
                renderEmpty={() => <p>Nothing to show.</p>} />
```

Or compose per entity with `normalize()`:

```tsx
import { normalize } from "@coffeejson/core";
import { RecipeCard, BeanCard } from "@coffeejson/react";

const doc = normalize(input);
<RecipeCard recipe={doc.recipes[0]} activeStepIndex={2} />
```

## Styling contract (frozen)

Every element carries a stable `cj-*` class. Import the default skin, override
its `--cj-*` custom properties, or skip the import and style from scratch:

| Class | Element |
|---|---|
| `cj-view` | document wrapper (beans render before recipes) |
| `cj-card` | every card (`<article>`) |
| `cj-recipe-card`, `cj-bean-card` | card variants |
| `cj-title` | card heading (`<h3>`) |
| `cj-badge` | "Recommended" badge inside the title |
| `cj-subtitle` | method · brewer line |
| `cj-fact`, `cj-fact-label`, `cj-fact-value` | label/value rows |
| `cj-origin-item` | one origin line inside the Origin fact |
| `cj-steps`, `cj-step`, `cj-step--active` | step list (`<ol>`/`<li>`), active highlight |
| `cj-step-time`, `cj-step-body`, `cj-step-target` | step internals |
| `cj-step-delta`, `cj-step-delta--none` | per-pour amount, and its reserved-column placeholder — present when the recipe shows a Pour column (see below) |
| `cj-generator` | the document's "Generated by …" line — once per document, after the cards |
| `cj-notes`, `cj-description` | roaster's notes / bean description |

Custom properties on `.cj-view`: `--cj-accent`, `--cj-fg`, `--cj-muted`,
`--cj-bg`, `--cj-border`, `--cj-radius`, `--cj-space`, `--cj-font`.

### Per-fact targeting

Every fact row also carries a stable `data-cj-fact` attribute, so a single fact
can be hidden or restyled with CSS alone — no config needed:

```css
[data-cj-fact="grind"] { display: none; }   /* hide just the grind row */
[data-cj-fact="dose"]  { font-weight: 700; }
```

Recipe ids: `coffee`, `water` (pour-over) or `dose` (espresso, coffee→yield),
`ratio`, `waterTemp`, `additions`, `grind`, `filter`, `pressure`, `preinfusion`,
`basket`, `time`. Bean ids: `roaster`, `origin`, `process`, `varietals`, `roast`,
`roasterNotes`.

## Display configuration

Every component (`CoffeeJSONView`, `RecipeCard`, `BeanCard`) takes an optional
`config` prop. Omit it and nothing changes: all sections show, measurements
render as authored, captions are English, and no extra classes are added.

```tsx
// Defaults — identical output to passing no config at all.
<CoffeeJSONView doc={doc} config={{}} />
```

### `show` — hide whole sections

Coarse, section-level toggles. `dose`, `ratio`, and `waterTemp` always show;
there are no field-level toggles.

```tsx
<RecipeCard recipe={recipe} config={{
  show: { grind: false, gear: false, espresso: false, generator: false },
}} />
```

### `labels` — re-word captions

Deep-merges over the built-in English captions, so you only specify what
changes. See `@coffeejson/core`'s `LabelSet` for the full shape (`facts`, the
`brew` timer strings, `beanFallback`, `badge`, and one table per closed
vocabulary: `methods`, `processes`, `stepKinds`, `roastLevels`, `grindSizes`,
`filterMaterials`, `producerRoles`; plus `decodeErrors`, one sentence per decode
reason, for a page that reports one).

```tsx
<RecipeCard recipe={recipe} config={{
  labels: { facts: { dose: "Coffee", waterTemp: "Temperature" } },
}} />
```

**A card never spells a token.** A closed vocabulary reaches the screen as a
label — `light_medium` reads "Light-medium", never "light medium" — and each
table is keyed by its vocabulary, so a token the format grows is a compile error
rather than a slug on a card. Re-word or localize one by token; a table merges by
token, and you may name a token this build has not heard of.

```tsx
<BeanCard bean={bean} config={{
  labels: {
    processes: { washed: "Lavado", natural: "Natural" },
    roastLevels: { light_medium: "Claro-medio" },
  },
}} />
```

An unrecognized token follows the spec's own fallback for its set: one that
defines `other` (`method`, step `kind`, `process`, filter material) shows the
`other` label, and the two ordered scales — `roast_level`, grind `size`, which
the spec says to ignore in favor of a more precise field — drop out of the row
instead. `producerRoles` is the one open registry among them, so an unrecognized
role shows as itself — the spec makes displaying it a MUST. A free-text field is
never touched: `drying_method` is the roaster's own word and passes through
exactly as written.

### `units` — convert measurements

`"as-authored"` (default), `"metric"`, or `"imperial"`. Converts mass
(gram⇄ounce), temperature (celsius⇄fahrenheit) and length (meter⇄foot, which
is what a bag's altitude is stated in); every other unit passes through
unchanged.

```tsx
<RecipeCard recipe={recipe} config={{ units: "metric" }} />
```

### `locale` — number formatting

A BCP-47 tag (default `"en"`) that drives digit formatting for measurements
via `Intl.NumberFormat`. Captions still come from `labels` — `locale` only
affects digits.

```tsx
<RecipeCard recipe={recipe} config={{ locale: "de" }} />
```

### `classNames` — additive styling hooks

One extra class per frozen `cj-*` part, appended alongside it — never
replacing it. Key names match the table above in camelCase (for example `card`,
`recipeCard`, `beanCard`, `factLabel`, `stepActive`).

```tsx
<CoffeeJSONView doc={doc} config={{
  classNames: { card: "brand-card", badge: "brand-badge" },
}} />
// → class="cj-card brand-card", class="cj-badge brand-badge"
```

### `components` — swap how a part renders

When re-wording, hiding, class hooks, and CSS are not enough — you want a
*different DOM* for a part — pass a replacement component. It receives the
part's semantic props and owns its markup entirely (the default `cj-*` element
is replaced, not wrapped; render `cj-*` classes yourself only if you want them).

```tsx
<CoffeeJSONView doc={doc} config={{
  components: {
    // Facts as chips instead of label/value rows:
    Fact: ({ id, label, value }) => <span className={`chip chip-${id}`}>{label}: {value}</span>,
    // Brand the "Recommended" badge:
    Badge: ({ label }) => <MyPill>{label}</MyPill>,
  },
}} />
```

Overrides must be pure (SSR-safe), like every component here. Empty facts are
still suppressed by the card, so a `Fact` override never receives a blank value.

**Scope:** `Fact` covers every label/value row — all recipe facts plus bean
process/varietals/roast. The bean's roaster link, origin list, and roaster's
notes, and the pour-schedule step row, are not overridable. To restructure
those — or the whole card — compose `RecipeCard`/`BeanCard`, or drop to
`@coffeejson/core`'s `normalize()` and own the markup.

### Step water

A step with a `to_water` target renders its cumulative total in
`cj-step-target`. When a recipe pours more than once, each targeted step also
renders its own pour amount in `cj-step-delta` — the initial fill unsigned
(`60 g`), later pours signed (`+120 g`), and `cj-step-delta--none` holding the
column where an increment is not derivable (`—`) — as a sibling after
`cj-step-body`, so a consumer can grid Pour · Total into aligned columns (the
default skin lays them inline). A recipe that never pours twice grows no Pour
column; there is no configuration knob.

## Brew timer

`useBrewAlong(steps, finishS)` is the clock; the components render its state. It
owns time-keeping *only* — wake-lock / vibrate / unload-guard stay with you (the
package never touches `window`/`document`/`navigator`, so it stays SSR-safe).

```tsx
import { BrewAlong, useBrewAlong } from "@coffeejson/react";
import { normalize, hasSchedule } from "@coffeejson/core";

const recipe = normalize(doc).recipes[0];
function Timer() {
  const brew = useBrewAlong(recipe.steps, recipe.finishS);
  // ...your own wake-lock / vibrate reacting to brew.running / brew.state...
  return <BrewAlong recipe={recipe} brew={brew} />;
}
```

Only offer a timer when there's something to count toward — `hasSchedule(recipe)`
is `false` for espresso or fully user-paced recipes.

### Variations

`<BrewAlong>` takes a `variants` prop. Each field maps to one component:

| Field | Options (default first) | Effect |
|---|---|---|
| `stepCard` | `"full"` \| `"compact"` | current-step card: full = step n/total + time + text + pour + total; compact = pour + total |
| `countdown` | `{ target: "next" \| "finish", format: "clock" \| "seconds" }` | count down to the next pour or to drawdown; `m:ss` or `5s` |
| `timeline` | `"dots"` \| `"numbered"` | step markers ●──◎──○ or ①②③ |
| `controls` | `"text"` \| `"icons"` | the control strip: labeled buttons, or the compact icon strip |

```tsx
<BrewAlong recipe={recipe} brew={brew} variants={{
  stepCard: "compact",
  countdown: { target: "finish" },
  timeline: "numbered",
}} />
```

`<BrewAlong>` is those three components plus a clock and controls. For a
different layout, arrange `<Countdown>`, `<StepCard>`, and `<Timeline>`
yourself — each takes `recipe` and the timer `state` (`<Countdown>` also
`elapsedS`).

### The other components

Three more components ship for arrangements `<BrewAlong>` does not cover. Each is
pure and props-driven like the rest, and each takes the same optional `config`.

| Component | Props | What it renders |
|---|---|---|
| `<StepList>` | `recipe`, `state`, `elapsedS?`, `config?` | the whole schedule as a vertical list — one row per step plus a finish row, each with its cue time, label and pour amount, and a connector that fills as the clock passes |
| `<PourCounter>` | `recipe`, `state`, `config?` | a large "pour n of N" counter over the steps that add water (a stir or a press is not a pour), or the finished label; renders nothing for a recipe that never pours |
| `<BrewControls>` | `brew`, `variant?`, `config?` | the pause/resume, next-step and reset controls — `"icons"` (default) or `"text"` |

`<StepList>` sets a `--cj-fill` custom property on each row, as a percentage of the
segment between that row's cue and the next. The default skin uses it to fill the
connector; a consumer restyling the list reads the same property.

```tsx
import { StepList, PourCounter, BrewControls, useBrewAlong } from "@coffeejson/react";

const brew = useBrewAlong(recipe.steps, recipe.finishS);
<>
  <PourCounter recipe={recipe} state={brew.state} />
  <StepList recipe={recipe} state={brew.state} elapsedS={brew.elapsedS} />
  <BrewControls brew={brew} />
</>
```

`<BrewAlong>` composes `<BrewControls variant="text">` for its own controls, so its
`variants.controls` switches the whole strip between labeled buttons and icons.

Style via the frozen `cj-brew*` / `cj-stepcard*` / `cj-countdown*` / `cj-timeline*`
/ `cj-steplist*` / `cj-pourcounter*` classes — import the default skin or roll your
own, same as the cards.
